# Direct-Y structure reuse — first-principles exact A/B experiment

## Redundant work and candidate

The opt-in full-year Y memo previously constructed `YBStructResult` inside `handleYear` for every Y; its first cache miss also constructed a second copy inside `yearRecords`. Three same-context Y requests therefore triggered **four direct service-level structure constructions**, despite one complete year-record build and two memo hits.

The new opt-in `SEER_NEXT_Y_STRUCT_REUSE=1`, **off by default**, stores the exact `YBStructResult` generated by a memo table build inside that entry. A Y request with direct-year memo enabled checks the table and its structure before doing any new `build_nonweave` work. A hit returns read-only pointers to both, a miss computes both together once, and an inadequate cache budget falls back to the original exact Y computation with one local structure build. Existing `R` threshold/promotion and LRU record eviction remain unchanged; the metadata is removed with its table.

The diagnostic `serviceYearStructBuilds` counts direct `build_nonweave` calls in `handleYear` and `yearRecords`; it does **not** count internal structure operations inside `compute_segment`. The existing 8MiB cache budget accounts only for `BatchRecord` payload and **excludes the extra cached structure's vector allocations**. This is intentional research accounting, not a hard process-memory limit.

## Exact acceptance gates

1. Keep the previous **144 complete Y JSON** results plus their six existing interop checks unchanged. In the independent new A/B, sample 6 year/calculation contexts × 2 trials × 3 service modes (unchanged native Seer, original 4/2 direct-Y memo, new opt-in 4/2 direct-Y+structure memo) × 3 complete Y queries: **108 additional complete replies** (252 across both experiments), each deep-equal to unchanged Seer. Record first-Y, two warm-Y, all-three times, process startup-to-first response, VmPeak, VmHWM.
2. In each three-Y context require direct-year memo builds=1, hits=2, evictions=0 and keys=1 for both variants. Require direct structure builds=4 in the control and =1 in the candidate. These exact counters demonstrate the intended elimination of redundant work.
3. Check six additional exact interop cases against unchanged native Seer: zero-byte cache, 1024-byte tiny cache, Y→R→Y, R→R→Y, same year in two calculation contexts, and one-year-only LRU eviction. Require exact builds, hits, keys, evictions, service direct-structure counts and complete native reply equality for every command.
4. Compare the candidate's first and repeated complete Y4999 replies under effective Linux `RLIMIT_AS=512MiB`. Read `/proc/PID/limits` and `/proc/PID/status`; fail on any error, mismatch or excess VmPeak. This is virtual address space, **not physical RAM enforcement**.
5. Report all per-context raw measurements, environment and exact evidence. A faster sum in one virtualized runner is not a universal performance claim, and CI pass alone is not a release decision. No change to `main` or production defaults.

## Caveats

There is some additional per-year structural metadata memory (small relative to the full-year record table in typical years, but not independently bounded by the payload budget). A future bounded-RSS mode must count actual resident memory, not infer it from `payloadBytes` or `RLIMIT_AS`. No speedup is assumed until the new completed experiment reports its results.
