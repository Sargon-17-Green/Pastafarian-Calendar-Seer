# RLIMIT_AS-aware D dispatcher, research-only opt-in — preregistration

Date 2026-11-07. Base successful [CI 42403588914](https://github.com/Sargon-17-Green/Pastafarian-Calendar-Seer/actions/runs/42403588914), 48-trial native frontier and [56_RNS_CAP_FRONTIER_RESULTS.md](56_RNS_CAP_FRONTIER_RESULTS.md). The experiment must **not** change production Seer, `main`, default research execution profiles or existing `SEER_DIAGONAL_THREADS` semantics with the feature OFF.

## Policy and rationale

Add experimental `SEER_NEXT_D_CAP_POLICY=1` only in the research hybrid/cold service. At each native D request, query **effective** Linux kernel `getrlimit(RLIMIT_AS)`, not the environment variable containing the originally requested cap. If finite and strictly below 768MiB, bound native D dispatcher workers to **1**. If finite and at least 768MiB, bound to **2**. If unlimited, do not override the existing requested/hardware/count limit. Never **increase** the number of requested workers, and preserve execution profile `memory`=1. Unknown values must be rejected, unsupported non-Linux policy must fail explicitly. Before dispatch, optionally append a four-column diagnostic row: requested D workers, selected D workers, effective cap bytes (0 = unlimited), and D record count. A kernel-address-space limit is not an RSS cap; even 768MiB + 2 workers can fail for other workloads.

## Comparison and acceptance gate

For two calculation JDNs 2461290/2461400, independently derive structurally distinct R years 4999/5000 from untouched Seer Y metadata and obtain eight full original Seer R/Y/D JSON replies per JDN. Test three effective RLIMIT_AS caps: **512,768,1024MiB**. Under each cap use both immutable two-slot initializer cache scopes `thread` and `process`. For each JDN×cap×scope run two fresh native research cold-probe processes: fixed D workers 1 at 512 or 2 at 768/1024 with scheduler disabled, and requested D=3 with scheduler ON, which must select exactly the matched fixed 1/2 workers based on *kernel readback*. This produces **12 paired contexts**, **24 candidate trials**, **192 full candidate native replies** plus **16 original oracle replies**. No coarser hash-only parity or dropped D commands is acceptable.

All 24 candidates must fully complete all eight requests, producing exact native JSON equal to unchanged Seer, under actual Linux `RLIMIT_AS` verified from `/proc/PID/limits` and VmPeak within cap. Verify three D diagnostics per policy run, with exactly requested=3, chosen=1/2 as specified, observed-cap bytes exactly equal to the measured limit, and record counts matching D windows 6/9/12. Retain existing exact native RNS/cache-scope traces (two-column-scope-independent native four-field schemas) and verify initial RNS cache misses in both distinct years. Record all response times and VmPeak/VmHWM for the fixed-vs-opt-in comparison; do not promise an unconditional speedup.

**Reject** on any full reply mismatch, unsuccessful capped request, wrong worker selection, wrong cap readback, missing trace, runtime regression against old defaults, or incomplete evidence. Full CI success means only this **empirical Linux research workload** passes; not a universal dynamic memory/throughput policy or authorization to adopt to production.
