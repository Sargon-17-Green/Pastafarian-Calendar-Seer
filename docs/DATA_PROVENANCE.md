# Algorithm-data provenance

## `prototype/data/gates_u16.bin`

The current prototype bundles **40,000 positive canonical gate gaps** (`0..40000`) as fixed algorithm data.
The corpus is derived from the canonical saved-sum Sauce semantics of the current Scroll.

Current SHA-256:

```text
2321775cd22a1156751fe506320d4afc47b27f391092645921df4b54d9ab49bb
```

Current corpus statistics: 40,000 gaps, minimum 42, maximum 963, sum 20,067,200.

The source generator is `prototype/tools/generate_gates_saved_sum.cpp`. The reproducibility gate
`prototype/scripts/check_saved_sum_conformance.sh` rebuilds the complete corpus with an independent exact Boost `cpp_int` reference, byte-compares it with
the checked-in file, then validates the same file independently through both corrected fast Sauce headers.

## Canonical semantic dependency

For each of the 12 final post-stirs, the six new bowl values are computed from one old-bowl snapshot.
Let `S` be the old bowl sum and `R = SAVE(S + 149*r)`. The same preserved value `R` selects the
lexicographic bowl permutation and is the additive sum term inside every bowl's `u`. Using raw `S`
inside `u` is noncanonical.

### HISTORICAL — SUPERSEDED

The previous checked-in gate corpus had SHA-256
`57d20ac6653e9cbd1d33a5e591bb6b65a39bc0c6ec90b3af1b978d3f7ec6fdbc` and sum 20,176,753.
It was generated by a common raw-sum error shared by the former v3/v12 validation paths. An
independent reference run in raw-mutant mode reproduces that exact historical digest; under the
corrected saved-sum semantics, 39,956 of the 40,000 gap records differ. The old digest and any
validation report based on it are archival evidence only, not a canonical baseline.

## Scope

The bundled file still covers positive gate indices only. Negative-gate support is not packaged in
this benchmark prototype; that pre-existing scope limitation is unchanged by the saved-sum correction.
